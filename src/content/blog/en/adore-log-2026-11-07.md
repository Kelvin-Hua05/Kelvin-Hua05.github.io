This is the second dev log for [ADoRE-DoE](https://github.com/Kelvin-Hua05/ADoRE-DoE). The project had only documentation and a package skeleton; now I started implementing the first algorithm of v0.1.

## What I did today

- Implemented `plackett_burman()`, which builds designs from normalised Hadamard matrices (Sylvester, Paley I / II, Kronecker). Every constructed matrix is verified against H·Hᵀ = N·I.
- Added support for center points, dummy columns, and reproducible randomization (explicit seed).
- Added `supported_runs()` to list the run sizes that can currently be constructed.

## Design decisions

- **Never silently alter the user's run count**: an invalid `runs` value raises an error and lists the supported sizes.
- **The factor limit comes from the math, not the code**: k ≤ runs − 1, with no hard-coded factor count. Design generation is independent of the number of responses.
- **Aliasing is part of the output**: PB designs are for main-effect screening only, so the design object carries an aliasing note in its `info` to avoid mistaking an interaction for a main effect.

## Open issues

- The designs have not yet been compared entry by entry with the classical cyclic PB tables. This needs a numerical regression test against a reference implementation in R (e.g. `FrF2`).
- The upper bound for automatic run selection (68) is not yet user-adjustable, and runs = 52 is currently unsupported.
- When the number of factors equals runs − 1, there are no dummy columns, so there are no degrees of freedom for error. Center points or replicates are needed.
- The research questions from yesterday (baseline definition, multi-response normalisation, CV bias in stopping rules, model mismatch between GPR and RSM) are still open.
